# Дополнительные случаи

[`cases.py`](cases.py) воспроизводит на стенде [cps-update-lab](https://github.com/alexqzm/cps-update-lab)
события, которых нет в его сценариях, — для правил, которые иначе проверялись бы только на
синтетике. Используются классы стенда (`Lab`, `Device`, `Gate`) и настоящие scii-agent и
scii-gate: квитанции проверяет агент, отчёты подписаны ключами устройств, решение принимает гейт.

| Случай | Что сделано | Ожидаемый исход |
|---|---|---|
| C1 | квитанция обрезана до 100 байт | FORMAT |
| C2 | квитанция подписана ключом нарушителя | KEY |
| C3 | в подлинной квитанции поднят номер версии, подпись прежняя | SIGNATURE |
| C4 | квитанция с решением «отказ», подписанная ключом гейта | DECISION |
| C5 | квитанция под другую политику, подписанная ключом гейта | POLICY |
| C6 | образ на байт короче, квитанция подлинная | SIZE |
| C7 | три неверных пароля управления, затем `stop` с паролем по умолчанию | DENIED ×3, OK |
| C8 | устройство L0 установило вредоносный образ, в отчёте SHA-256 подменён на допущенный | подпись отчёта недействительна |
| C9 | выпуск ТК-1 1.1.0 без аттестации происхождения s22 | решение гейта 20 (запрос свидетельств) |

Случаи C1–C6 — на устройстве L2 с ТК-1 1.0.0, которое забирает пакет 1.1.0 с подменённой
квитанцией или образом. Гейт стенда квитанций с решением «отказ» не выдаёт; формат SCII-R v1
их допускает, поэтому C4 показывает, что агент отвергает и такие.

```bash
cpslab --home LAB scenario matrix
cp -a LAB CASES
PYTHONPATH=<cps-update-lab>:<scii-gate> python labcases/cases.py --home CASES
python -m sciitel export --lab-home CASES --profile <cps-update-lab>/cpslab/data/profile.json --out events.jsonl
```

Выход 0 — каждый случай дал ожидаемый исход; исходы записываются в `CASES/cases.json`. Набор
[`dataset/cases-0.1.0`](../dataset/cases-0.1.0/) получен так; CI повторяет это на закреплённых
коммитах и сравнивает.
